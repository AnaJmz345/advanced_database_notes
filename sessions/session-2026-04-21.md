## What I understood

### Definition of transactions
A transaction is a way to execute multiple operations in the database where there can’t be half-done operations — either everything is completed or nothing is applied.

For example:
```sql
BEGIN;

UPDATE accounts SET balance = balance - 100 WHERE id = 1;
UPDATE accounts SET balance = balance + 100 WHERE id = 2;

COMMIT;
 ```
 If something fails in the second query, you don’t want the first one to stay applied.
 so, you do a ROLLBACK which will cancel everything, like nothing happened

 ### Transactions have ACID properties (ruled that make transactions reliable)
Atomicity: Everything must succeed or everything is undone. No partial changes.

Consistency: The database always stays correct and valid.cIf a rule says balance cannot be negative, this will fail: 
UPDATE accounts SET balance = -500 WHERE id = 1; In here, the transaction will be rejected so the db doesn't end in an invalid state.

Isolation: Transactions don’t mess with each other. For example, two users try to buy the last product at the same time; without isolation both could buy it (wrong) and with isolation only one succeeds, the other fails or waits.

Durabilty: Once you commit, the data is permanently saved (COMMIT). After this, even if the server crashes, the changes are still there when it restarts.

### Other relevant concepts
**Savepoint**
A savepoint is like a checkpoint inside a transaction.
In the following example, only the last part is undone, not everything:

```sql
BEGIN;

INSERT INTO orders VALUES (1);

SAVEPOINT step1;

UPDATE inventory SET stock = stock - 1;

ROLLBACK TO step1;

COMMIT;
```
**Autocommit**
Autocommit means every query is saved automatically.
If you don't store the sql statement in a transaction, for example this: UPDATE users SET name = 'Carlos'; you cannot undo it after running it.

### Stored procedures
A stored procedure is SQL code saved inside the database that you can reuse.

It helps you:

* Avoid repeating logic
* Run multiple operations together
* Control transactions

For example 

```sql
CREATE PROCEDURE transfer_money()
BEGIN
  START TRANSACTION;

  UPDATE accounts SET balance = balance - 100 WHERE id = 1;
  UPDATE accounts SET balance = balance + 100 WHERE id = 2;

  COMMIT;
END;
```
If you want to use the transaction you can just call transfer_money() instead of rewriting the whole block whenever you need it.

### Functions
Functions are simpler, they are mainly used to return a value, especially for calculations or simple logic inside queries.

**Example**
```sql
CREATE FUNCTION calculate_total(price DECIMAL(10,2))
RETURNS DECIMAL(10,2)
BEGIN
  RETURN price * 1.16;
END;

-- You use it with
SELECT calculate_total(100);
```
