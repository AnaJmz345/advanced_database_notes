## What I understood

### ORM
- An ORM, or Object-Relational Mapping, is a tool that connects the code with the database. Instead of writing SQL directly all the time, the developer can work with objects or classes, and the ORM translates that into database operations. For example, in a backend project, a User class can represent a users table in the database. So, instead of manually writing every SELECT, INSERT, or UPDATE, the ORM helps manage that connection in a cleaner way.

For exmaple, instead of doing this:
```sql
SELECT * FROM users WHERE id = 1;
```
you do this with an ORM:
```sql
User user = userRepository.findById(1);
```
- The idea is to represent the db as a class and each register/line is represented as an object.
- There are different libraries and frameworks that apply this ORM, depending on the technology you are using.For example, for springboot, JPA/Hibernate is usually used as an ORM. Th ORM translates by itself the easy to understand commands to real sql queries.

### DB migrations
DB migrations are a mechanism used to keep control of the changes made to the database structure. It is kind of like version control for the database, because every change, like creating a table, adding a new column, renaming a field, or changing a constraint, is saved as a migration file.

For example, if I am working on a new feature and that feature needs a new column in the database, that change should not just be made manually. It should be added as a migration, so it can be applied in the correct order and in different environments, like development, testing, and production. This helps the team keep the database organized and updated as the project changes.

### Benefits of db migration

- Reduced IT expenses
- Improved performance
- Data consolidation
- Cutting-edge technology adoption
- Enhanced data security
- Disaster recovery and business continuity
