## Topics covered
- vEctor Search
- Use of hugging face model all-MiniLM-L6-v2 which is a sentence-transformers model: It maps sentences & paragraphs to a 384 dimensional dense vector space and can be used for tasks like clustering or semantic search. This model could be applied in a chatbot by asking do you remeber the last time when we talked about...

## What I understood
- Vector search does not work by matching exact words, instead it compares meanings using embeddings (vectors).
- The hugging face model all-MiniLM-L6-v2 converts text into a 384-dimensional vector, so similar sentences end up close to each other in that space.
- When we search, we are not looking for keywords but for vectors that are closer using a distance metric (like cosine similarity).
- The lower the distance (or better similarity score), the more relevant the result is.
- This allows the system to answer questions even if they are not written exactly the same as in the text.
- I also understood that even unrelated questions can return "kind of related" results because the model connects concepts (like princess → royalty).
 
## Something new I learned:
- I learned how embeddings actually work in practice, not just theory.
- I understood that vector databases store text as numerical representations and not as plain text.
- I learned how cosine similarity is used to compare vectors and find the closest matches.
- I realized that semantic search is more flexible than traditional search because it understands meaning, not just exact words.
- I also learned that results are ranked by similarity score, and the best answer is usually the one with the lowest distance.
