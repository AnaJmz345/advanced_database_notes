## What I understood

### What is a schema?
Schemas are logical containers of tables, views, and other objects inside a database. 
Its key benefits are:
- They provide organization and control because instead of having 100 tables all mixed, you can group them by purpose.
- Provide security by controlling who can access what. They are a way of saying this group of tables belong to this user/system.For example: HR team can access HR schema

### Database backups are done through 2 types:

*Schema backup* 

**Why is it important?**
- Insteaad of baacking up all the database, you backup certain schemas because they are groups of the db that are for  aspecific purpose or domain and if you have something well modularized, the key modules may use their belonging schema so if that module brakse you can quickly and easily restore the part of the db that needs it, instead of doing it for all the db. Also, backing up the full databaase can be slow to restore and export if it is very large.

**What is a schema backup**
It is a file with all the DDL statements necessary to create the structure of the tables in that schema. So, it has CREATE and ALTER, etc statements that define the tables, constraints, indexes and relationships. The tables need to be created in the correct order (parent tables first and then the child tables) to avoid errors due to the FK.

*Data backup*
**What is it?**
It is a file with the DML statements, especially the INSERTS, because it saves the actual data that is inside the tables.


### Types of exports
Export is just another way of saying take data out of the database and save it into a file. So exports can create that backup file and import can restore the db from the file.

**Single object export**
You export only one thing, for example one table (users) or one view. It is used when you only care about one part.

**Schema export**
Export everything inside a schema

**Full database export**
It includes all schemas, all tables and all data. This is the “full backup”, it is used for migrations, disaster recovery and cloning environments.
